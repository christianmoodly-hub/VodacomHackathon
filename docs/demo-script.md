# Demo script

Aim for under five minutes. Use only the synthetic file already loaded. Do not type a real name, place, or case number.

This page is the in-repo fallback for the Level 2 explanation, the Level 3 coordination brief, and the bonus audit line. Quick Web is not run from this repo.

1. Open the app. Read the footer: "Synthetic data only. For authorised human review. No action should be taken from this output." Point at the two windows, 21 days for the same area and 7 days for different areas, and say they are reviewer assumptions, not columns in the CSV. If the API is not deployed, the header shows Offline mode.

2. In Links named in the data, open CASE-SYN-1000 and CASE-SYN-1008. Show both records side by side: Area-2 and Area-1, 68 days apart, and the line that area and timing do not support this named link.

3. In Area / timing leads, open CASE-SYN-1005 and CASE-SYN-1011. Show one day apart, Area-1 and Area-3, and that neither record names the other. Mention CASE-SYN-1001 and CASE-SYN-1006 as a separate same-area pair, eight days apart, so the August set is not the only rule hit.

4. Click Generate coordination brief. Read the possible link, one evidence line, and "This requires human verification before any action is taken." In offline mode the brief is the local template.

5. Choose Needs more info and click Record decision. Show the chip and the session history. Decision history lists server rows when the API is up, and says the server history is unavailable in offline mode. The click does not remove the lead.

6. Stop. If time remains, click Add fictional example, then Run analysis, and show the new record appear only after the run. Reset restores the original 12 records.
